Activity answers one question: what did the agents get done in this view, and where did they struggle? It counts commits, prompts, sessions and active days, and it lists error loops, sessions near the context limit, flaky tools and failed test runs. Its heading, Needs attention and Project metrics show no cost figure; [Cost](/ai-ledger/pages/cost/) leads with cost. The Sessions tab and the sheets show each session's estimated cost.

The page follows the filters in the [scope bar](/ai-ledger/everywhere/filters/#scope-bar) under the navigation. Every figure below describes the selected project, time range and source.

Activity has two views of the same sessions. This page describes **Overview**, the measured view. **Judgments** shows how Claude Code's `/insights` judged them; see [Judgments](/ai-ledger/pages/insights/).

## Views

A switch above the heading picks the view: **Overview** or **Judgments**.

- Overview is the default. Judgments is in the address as `view=judgments`, so a reload or a copied link opens the same view, and Back returns to the view before.
- A switch keeps the project, the range, the source and Include automated. It drops the filters only the other view has: Overview's session search, near-limit filter, selected day or week and tab, and the Judgments view's outcome and friction filters.
- With **Codex** or **Grok** as the source, Judgments cannot be picked, and the text beside the switch says why, naming the agent: "Grok writes no facets: /insights judges Claude Code sessions only." A link to the Judgments view with Codex or Grok as the source opens Overview.

## Filters

| Control | Values |
| --- | --- |
| Project | A searchable list of projects, plus "All projects". |
| Time range | 7d, 14d, 30d, 90d, All. The default is 30d. |
| Source | All, Claude Code, Codex, Grok. |
| Include automated sessions | On or off. A tooltip names the file that lists more automated projects. |

The filters live in the page URL. The project filter changes only through these controls, or through a "Filter dashboard to" button in a sheet; selecting a project or session elsewhere opens a sheet and leaves the filter alone. See [Filters](/ai-ledger/everywhere/filters/) for how they behave on every page.

A selected day or week is cleared in the same step as any change of project, range or source.

## Layout

The page reads top to bottom: the view switch, the heading with the prompts interrupted line, Needs attention, the work chart, Work health, then the [tabs](#tabs) that hold the tables, then the [Activity calendar](#activity-calendar). At 1440×900 the work chart and the tab list fit in the first screen. The page has no section index and no drawers.

## Panels

### Overview

**Shows** the heading, which answers "what got done?":

> 30 commits from 212 prompts, up from 20 commits

**Figures**

- Commits and prompts of the view. Sessions and active days are in the [Sessions tile](#work-health).
- With one project selected, the heading adds "on" and the project. With the All range, it adds "since" and the first day with a session, and shows no change.
- Commits show their change against the previous period of equal length: "up from", "down from", or "unchanged".
- With no requests in the view, the heading reads "No agent activity in the last 30 days." (or "yet" for All). With a source selected, it names the source in place of "agent".
- A line under the heading gives the share and count of prompts interrupted, with its change (marked worse when it goes up), then the turns and tool calls per prompt: "11.2% of prompts interrupted (28 of 250), up from 10.6%; 4.8 turns and 7.3 tool calls per prompt."

**Banner** "Automated projects file ignored" appears under the navigation, on every page, when the automated projects file cannot be used. It names the file and the reason. See [Filters](/ai-ledger/everywhere/filters/#include-automated).

### Needs attention

<ThemedImage dark={attention} light={attentionLight} alt="Activity's Needs attention card: a short list of error loops, sessions near the context window, failing tools and failed test runs, each with an action." />

**Shows** every problem found in the view, each with an action. The card opens just under the heading. It is hidden when the view has no requests.

**Figures**

| Line | Condition | Action |
| --- | --- | --- |
| N error loops: a tool failed 3+ times in a row. | At least one error loop. Marked as needing action. | See loops opens the Loops and tests tab, on Error loops. |
| N sessions reached 80%+ of the context window. | At least one session at 80% or more. | See it or See them opens the Sessions tab, limited to those sessions, nearest the limit first. |
| N tools fail over 10% of calls, worst *tool* (rate). | A flaky tool: one that failed more than 10% of at least 20 calls. | See tools opens the Tools and MCP tab with those tools first. |
| N failed test runs of M. | At least one failed test or build run. | See tests opens the Loops and tests tab, on Failed test runs. |

Each action scrolls to its tab and moves the focus into it.

The card's title reads "N things to look at". With none of the four, it reads "Nothing needs attention".

### Work per day, or per week

<ThemedImage dark={work} light={workLight} alt="Activity's Work per day chart: commits per day, stacked by project, with errors per 100 calls on a thin track under the bars." />

**Shows** two tracks on one row of days or weeks, from the first day with a session to the end of the range: the work as bars on top, errors per 100 tool calls as a line on a thin track under them. Idle days show as zero.

**Figures**

- The bars count Commits, Prompts or Sessions, as chosen. Commits is the default. The choice is kept in the browser.
- With several projects, each bar stacks the projects that have a color of their own, as Cost does, and puts every other project, and sessions with no project, in Other. With one project, or with no project that has a color, the bars are plain.
- The lower track shows errors per 100 tool calls, against its own scale on the left (0 and its top). The failed count stays in the tooltip. A view with no tool calls shows no lower track or legend entry.
- A bar with fewer than 50 tool calls, when another has 50 or more, draws its rate as a hollow dot and does not set the scale; a rate above the scale stops at the top of the track. The legend keys the hollow dot "Under 50 calls".
- A label names the peak bar. It stays inside the plot: near an edge it slides in, and a chart narrower than the label draws none.
- The newest day's or week's label always shows, right-aligned on its bar, at every width. A label it would overlap is hidden.
- The chart's box is 216px tall at the default text size, 28px more with the zoom slider. At a larger browser text size the box grows by the room its labels and the rate track need, and the bars keep their height. A view with no tool calls has no rate track, and the bars use its room.
- The tooltip lists the commits, prompts and sessions of the bar, the project parts of the chosen measure, errors per 100 calls, and failed tool calls out of all tool calls.
- When the span from the first day with a session to today is over 60 days, the chart shows one bar per week, starting Monday on the machine's clock, and the title reads "Work per week". A week bar is labeled "Week of Oct 5". The week that holds the end of the range reads "so far"; a first week cut by the start of the range reads "from" its start date. Commit and prompt totals equal the sum of the bars. A session counts once in each week it touches, so the Sessions bars can add up to more than the total.

**Controls**

- **Commits, Prompts, Sessions** switch the measure.
- Select a bar to select its day or week. With the keyboard, focus the chart, use the arrow keys (Home and End jump to the ends) and press Enter. An idle bar selects nothing.
- A chip beside the metric switch names the selection, "Nov 4" or "Week of Nov 2". Its ✕ clears it. Escape on the chart clears it too: the first Escape ends a reading with the arrow keys, the next one clears the selection. Escape in a sheet leaves it.
- The selected bar is a tinted band with an accent frame across both tracks. It stays while you read other bars and when new data arrives. A selection the chart has no bar for, such as a week on a chart by day, or one the zoom leaves out, marks no bar, and the chip still names it.
- After a selection or a clear, a screen reader hears one sentence: "Week of Sep 7, 2026 selected; the tabs below show its days." (a day's reads "its figures"), "Week of Sep 7, 2026 is still selected; …" for the bar already selected, then "… is already selected; …" if you select it once more, and "Selection cleared; the tabs below show the whole range." after the chip's ✕ or Escape. A reading with the arrow keys replaces it. A selection changed outside the chart, such as by the tab note's "Show the whole range", says nothing and drops the sentence. Opening a link with a selection says nothing.
- **Zoom.** In a view of 14 bars or more, days or weeks, a slider sits under the bucket labels. Drag it, or its handles, to narrow the bars the chart draws. With the chart focused, plus (or `=`) halves the bars shown and minus doubles them, around the bar you are reading (the newest when you read none), down to 7 and up to every bar. While the chart is zoomed, a **Show all days** button (**Show all weeks** on a chart by week) beside the legend shows every bar again and returns focus to the chart. After each change the chart says which days or weeks are shown, for a screen reader. The arrow keys, Home and End still reach every bar: when one reads a bar outside those shown, the bars shown move to include it. Views of fewer than 14 bars have no slider and no zoom keys. Zooming changes nothing else: the range, the totals, the selection, the tabs and the URL stay as they are, the data table still lists every bar, and both tracks keep the scales of the whole view. The zoom resets when the view changes: the measure, the range, project, source or Include automated sessions, or the first bar moves. It stays when you select a bar and when new data arrives.
- New data arriving in the background leaves the bar you are reading read.
- **Show data table** opens a named table under the chart: one row per day or week, the measure by project with Other, its total, and errors per 100 calls. It is closed on every page load.

A selected day or week narrows every tab to its days in the view: Sessions (each session's figures for those days), Project metrics, Tools, MCP servers, skills and hooks, Error loops and Failed test runs. A week counts only its days from the start of the range to today, for every figure, active time included: a first week cut by the start of the range covers only its days in the range. The active tab stays. A selection drops the session search, the near-limit filter and the Sessions sort. A note at the top of the tab names the days it counts, such as "Oct 7 – Oct 11, 2026 only.", and offers "Show the whole range", which moves the focus to the chart. The heading, Needs attention, the chart and Work health keep the range's figures. A tile or a Needs attention action reports the range, so it clears the selection before it opens its tab.

While a new range or project loads, the chart still shows the previous view and selects nothing.

The selection is kept in the URL, as `day=2026-11-04` or `week=2026-11-02` (the week's Monday), without a history entry. A date that is not a real calendar date reads as none, and so does a `week=` that is not a Monday. A week the view does not reach is dropped from the URL.

### Work health

<ThemedImage dark={vitals} light={vitalsLight} alt="Activity's Work health row: tiles for sessions, errors per 100 calls, test runs passed, subagents and output speed, each with its change against the previous period." />

**Shows** five tiles, under the work chart. Each tile is a link or a button to the place that explains it. Each shows its change against the previous period of equal length, as ", up from X", ", down from X" or ", unchanged". The All range shows no change.

| Tile | Figure | Note under it | Marked worse when | Opens |
| --- | --- | --- | --- | --- |
| Sessions | Sessions in the view | "N active days, across M projects; median session X, Y active in all, Z thinking." The thinking shows when the view records it. Active days show their change too. An active day is a day with at least one user prompt; a session that works alone on a day with no prompt does not make it active. | Never judged. | The Sessions tab. |
| Errors per 100 calls | Failed calls per 100 tool calls | "N failed of M tool calls." | It goes up. | [Errors](/ai-ledger/pages/errors/), for the same project, range and source. |
| Test runs passed | Share of test and build runs that passed, or "n/a" | "N passed, M failed of K test or build runs." | It goes down. | The Loops and tests tab, on Failed test runs. |
| Subagents | Share of tokens that came from subagents | "of tokens came from subagents." | Never judged. | The Projects tab, sorted by Subagents. |
| Output speed | Output tokens per second of model time, as "98 tok/s", or "n/a" | "X waiting on the model and Y running tools, in N sessions.", or "No session in this view records model time." | It goes down. | The Sessions tab, sorted by Tok/s, fastest first. |

The Output speed tile draws a small line of output speed per bar of the work chart, when two bars or more hold a session that records model time. A session counts in the bar of its first request in the view. When every session in the view is a Codex session, the tile gives way to a note under the row: "Output speed: Codex transcripts record no model time."

A session's active time leaves out every pause over 20 minutes. Two figures that display the same value read "unchanged".

Model time and tool time come from the `cost-state` line that Claude Code writes when a session ends, in versions from about late October 2026. A Grok session's model time is the API time each of its turns reports; Grok reports no tool time, so it counts in model time only. Codex sessions and older Claude Code sessions record none, and count in neither figure; see [Supported agents](/ai-ledger/concepts/supported-agents/) for what each agent records. Output speed divides the output tokens of the sessions that record model time by that model time. These are whole-session figures: they include subagent work and the session's time outside the range. Model time can exceed active time, because subagents run at the same time. On a store from an earlier version, run `ai-ledger rebuild` once, with the app stopped, to fill them for sessions already ingested; see [Upgrade and rebuild](/ai-ledger/start/upgrade/).

## Tabs

Four tabs under Work health hold the tables: **Sessions**, **Projects**, **Tools and MCP**, **Loops and tests**. Sessions is the default. The tab is kept in the URL as `tab=projects`, `tab=tools` or `tab=loops`, without a history entry; an unknown tab reads as Sessions.

The tab list is one tab stop. Left and Right move between the tabs and wrap, Home and End jump to the ends, and Enter or Space opens the tab under the focus. Moving the focus alone opens nothing.

The Sessions, Project metrics and Tools tables sort by a column: select a header; the sorted header carries `aria-sort`.

### Sessions

**Shows** every session in the view, one row each. Its How measured toggletip says a session counts here when it has a request in the range, and that the Judgments view counts sessions by their start time, so the two totals can differ slightly.

**Columns**

| Column | Meaning |
| --- | --- |
| Session | Title, or its id; under it the start time, git branch and short id. |
| Project | The session's project. |
| Active | Active time. Pauses over 20 minutes are left out. |
| Model | Model time: time waiting on the model, over the whole session, or "–" when the session records none. |
| Tok/s | Output speed: output tokens per second of model time, over the whole session, or "–" when the session records no model time. |
| Prompts | User prompts. |
| Tokens | Tokens of the session. |
| Est. cost | Estimated cost at API list prices (Grok's reported cost for Grok). |
| Peak context | Largest request. A chip shows the share of the context window when it is 80% or more. |
| Failed | Failed tool calls. |
| Compactions | Context compactions. |
| Commits | Successful `git commit` calls. |
| Tests | Test and build runs, passed of run, or "–" when none. |

**Controls**

- Search by title, session id, project or branch.
- **Near context limit only** limits the list to sessions at 80% or more of the context window.
- **Columns** opens a list with one checkbox per column except Session. Untick a column to hide it at every width. Tick a column the window's width hides to keep it at every width. **Reset columns** drops every choice. The button reads "Columns, N hidden" while you hide N columns. The browser keeps the choice for every view; the URL does not. See [Columns](/ai-ledger/everywhere/data-tables/#columns).
- Every column except Project sorts, over the whole matching list on the server. Without a chosen sort, the order is newest first; with the near-limit filter, nearest the limit first; with a day or week selected on the chart, by cost on those days, all of them on one page. Sessions with no model time sort last under Model and Tok/s, in either direction. On a narrow window some columns hide; every sorted column always shows, even a column you hid. Hiding a sorted column takes it out of the sort and leaves the other keys. The hint under the controls says the whole order, such as "250 sessions, costliest first, then most prompts first."
- **Sort by several columns** sorts by up to three columns. While it is ticked, a header press adds its column as the last key, most first; a second press reverses it; a third removes it. Shift with a press does the same with the box unticked. At three columns, a new column replaces the third. Without the box or Shift, a press sorts by that column alone. Each sorted header shows its arrow and its rank. See [Sorting](/ai-ledger/everywhere/data-tables/#sorting).
- Each row starts with a checkbox named "Select" and the session's name. Tick it, or click anywhere in its cell, to select the session; the sheet does not open. Up to four sessions can be selected; at four, the other rows' boxes are disabled. A bar above the table says how many are selected, and **Clear selection** unselects them all and moves the focus to the search field. The selection lasts through Show more, a sort, a search, the near-limit filter, a refresh and a tab change. It clears when the project, range, source, Include automated, or the selected day or week changes. See [Selection](/ai-ledger/everywhere/data-tables/#selection).
- The rest of a row opens the session sheet.
- **Show more sessions** loads the next page.
- The search text and near-limit filter are kept in the URL and restored on reload. The sort and the selection are not kept.
- With a day or week selected, every figure is those days', except Model, Tok/s, Peak context and Compactions, which stay whole-session figures; a tooltip says so.

#### Compare sessions

With two or more sessions selected, **Compare** in the selection bar shows a "Session comparison" table between the bar and the Sessions table. Select it again to hide it. The table has one column per selected session, in the order you selected them, and one row per figure: Project, Start, then every Sessions column from Active to Tests. A column you hid, or one the window's width hides, still has its row. Each figure reads as its Sessions cell does, in the same format. A figure a session does not record reads "–", and when a compared session records no model time, a note under the table says what that "–" means.

Each figure keeps the scope it has in the Sessions list:

- Start is the session's actual start, even when the session started before the range.
- Active covers the whole session, unless a day or week is selected; then it covers those days.
- Model, Tok/s, Peak context and Compactions are whole-session figures. With a day or week selected, a toggletip on their row says so.
- Prompts, Tokens, Est. cost, Failed, Commits and Tests count the range, or the selected day or week.

The comparison makes no request: it reads the rows the list has loaded. A refresh updates each compared session the list holds. A session that a search leaves out of the list keeps the figures the list last showed for it.

Each session's column header holds its name, which opens the session sheet, and a **Remove** button, which unselects it. Under two sessions, the comparison closes.

The comparison leaves out the figures only the session sheet has: tool time, lines changed, the model mix and the judgment. It has no link of its own and marks no best or worst value. See [Comparison](/ai-ledger/everywhere/data-tables/#comparison).

### Projects

The Projects tab holds the Project metrics table.

**Shows** one row per project in the view, ordered by sessions, most first. There is no cost column.

**Columns** Project, Sessions (with a bar), Tokens, Subagents (share of tokens), Tokens / prompt, Commits, Errors / 100, Error loops.

With three or more projects, the Errors / 100 and Error loops cells are tinted when far from the median project, with a ▲ or ▼ mark and a key above the table. A project whose errors per 100 calls are 1.5 times the median or more is marked worse; an error-loop count that is 2 or more and above the median is marked worse. Hover a tinted cell for how far.

A row opens the project sheet. Every column header sorts, in the browser.

### Tools and MCP

**Tools** shows every tool called in the view, most calls first.

**Columns** Tool, Calls, Failed (failure rate), p50 and p95 (median and 95th-percentile time from `tool_use` to `tool_result`).

See tools in Needs attention puts the tools failing over 10% of at least 20 calls first, until you choose a column. A row opens the tool sheet.

Under Tools, three more tables: **MCP servers** (Server, Calls, Failed), **Skills** (Skill, Calls, Failed) and **Hooks** (Hook, Runs, Failed, Avg). A hook is named by its command cut to the last segment of each path, with its event under it. A row of the MCP servers or Skills table opens its sheet. Hooks have no sheet.

### Loops and tests

Two lists side by side, each headed with its count, each showing its five newest rows. **Show all N** expands a list in place to every row the page carries; **Show fewer** folds it back. When the page carries fewer rows than the count, the button reads "Show the 50 newest", and the list says "Showing the 50 newest of N".

**Error loops** are the same tool failing three or more times in a row within a session.

**Columns** Session (opens the session sheet), When, Project, Tool, Failures, and an "Open in Errors" link to the loop's first failure on [Errors](/ai-ledger/pages/errors/).

**Failed test runs** are the test and build runs that failed. The count is every failed run in the view.

**Columns** Session (opens the session sheet), When, Project, Command, and an "Open in Errors" link to the failure on Errors.

## Activity calendar

<ThemedImage dark={calendar} light={calendarLight} alt="Activity's calendar over the last 13 weeks: a heading, a key of four shades with their commit counts and the day recording starts, month and weekday labels, and a grid of 13 week columns from the left edge. The first two columns hold no cells; the days since recording started are shaded by commits." />

**Shows** the weeks since recording started, up to the last 53, as a grid under the tabs: a column per week, a row per weekday from Monday, a cell per day. It answers "when do I work with agents, and which days stand out?". It follows the project, source and Include automated sessions, not the time range: changing the range leaves the calendar as it is.

**Figures**

- A cell is one day. The span runs from the Monday of the first recorded day's week to today, and covers at least 13 weeks and at most 53. A store recorded for 11 weeks shows 13 weeks, the first two with no cells. Recording that started more than a year ago shows the 53 weeks from the Monday 52 weeks before this week's Monday.
- The shade is the work chart's measure, Commits, Prompts or Sessions. The calendar has no switch: change the measure on the work chart. The heading line and the key name it.
- A wide window has room for all 53 weeks. A narrower one shows at most the newest weeks that fit, 26 in a 343px box, and never scrolls sideways. The cells keep the size the window gives them, and the grid starts at the left edge, so a short history leaves room on the right. A larger browser text size widens the label margins, which can make the cells a little smaller. A cell is never smaller than 10px. When not all 53 weeks fit, a much larger text size makes the cells grow so the weekday labels never touch: at twice the text size a 343px box shows 20 weeks of 12px cells instead of 26 weeks of 10px cells.
- The shade is a step. Steps are cut at the median, the 80th and the 95th percentile of the days with any of the measure, over all 53 weeks, so a day has the same shade at every width. Agent work comes in bursts, so the darkest step holds about one active day in twenty. There are up to four steps, and fewer when the days have few distinct values.
- The key above the grid gives each step's numbers, such as "1–2", "3–8", "9+". A step that holds one value shows that number.
- A day with none of the measure is an empty cell. A day before the first recorded day under the same filters has no cell. When that first day is inside the weeks shown, the key ends with "Recording starts Sep 8, 2026". A day after today, which a machine whose clock runs ahead can record, has no cell and does not count in the steps.
- Weekday labels (Mon, Wed, Fri) sit left of the grid and month names above it. A month name that would touch the next one, or run past the box, is left out.
- With none of the measure in the weeks shown but some in the year, the label reads "No commits in the last 26 weeks."; with none at all, "No commits yet."
- Under forced colors a shade is a size: a square in the system text color that grows with the step, and an empty day is an unfilled square. The key's swatches follow.

**Controls**

- Point at a cell, or focus the calendar and use the arrow keys, to read a day in a tooltip: the weekday and date, then its commits, prompts and sessions, whatever the measure, with the shade's swatch on the chosen one. An idle day reads "No activity". A screen reader hears the same as one sentence, such as "Wednesday, Nov 4, 2026: 12 commits, 40 prompts, 6 sessions." With three or more steps, the sentence for a day in the darkest step ends with "Among the busiest days for commits."; the tooltip does not say it.
- Left and Right move a week, Up and Down a day, Home and End go to the first and last day. With nothing read, Right and Down read the first day and Left and Up the last. The keys stop at the ends. Up and Down do not scroll the page. See [Keyboard and screen reader](/ai-ledger/everywhere/keyboard-screen-reader/).
- Select a day with a click, a tap, or Enter on the day read. Only a day with activity can be selected; Enter on an idle day does nothing and keeps the reading.
- A selection works as on the work chart: `day=` in the URL, every tab narrowed to that day, the session search, near-limit filter and Sessions sort dropped. The work chart's chip names the day, and a chart by day frames its bar. A selected week from the work chart is framed as one column. A selection the calendar shows no cell for draws no frame.
- After a pick the page scrolls to the tabs and moves the focus to the selected tab's panel, which names the day and offers "Show the whole range".
- Escape ends a reading. With nothing read, Escape clears the selection. Escape closes a tooltip the pointer opened even when the focus is elsewhere.
- After a change of filters or range, a pick does nothing until the page's new figures arrive, and after a change of filters, until the new calendar arrives too. A refresh or an ingest keeps picks on while newer figures load, and newer figures keep the day you read.
- Before its first figures arrive, the section reads "Loading the calendar…".
- If the calendar cannot load, its section reads "Could not load the calendar" with the reason and a **Retry** button. A calendar already on screen stays: after a change of filters the line adds "Still showing the calendar of the earlier filters; it cannot be selected.", and after a failed refresh "Still showing the last one loaded.", which can still be selected. While Retry runs, the button reads "Retrying…" and keeps the focus. If the calendar arrives while the button still has the focus, the focus moves to the calendar. If you change the filters before it arrives, the Retry is cancelled and the focus returns to the page. A refresh or an ingest asks again quietly: the line stays as it is, and goes when the calendar arrives. The focus stays where it is, unless it is on the Retry button: the button goes with the line, and the focus returns to the page.

**The range.** The tabs count only the days in the range, so a pick outside it first widens it. The page sets the smallest of 7, 14, 30 or 90 days that holds the day, or All. Only a day with activity says so: its tooltip adds "Outside the last 30 days. Selecting it sets the range to the last 90 days.", and its sentence "Outside the last 30 days; selecting it sets the range to the last 90 days." After the pick, a screen reader hears "Oct 1, 2026 selected; the range is now the last 90 days, and the tabs show its figures." A day inside the range says "Nov 4, 2026 selected; the tabs show its figures." Back restores the earlier range. Escape on a selection says "Selection cleared; the tabs show the whole range."

**Show data table** opens a named table under the grid, such as "Commits per day, by week": a row per week shown, "Week of Nov 2, 2026" (", so far" for this week), a column per weekday from Mon to Sun, and Total. A day with no cell shows a dash. It follows the measure and is closed on every page load.

## Sheets

A sheet opens beside the page and does not change the filters. Its state is in the URL, so Back, reload and shared links agree with it. The same sheets open over every page, from a row, a link, the [command palette](/ai-ledger/everywhere/command-palette/) or a [context menu](/ai-ledger/everywhere/context-menu/). [Sheets](/ai-ledger/everywhere/sheets/) describes each once:

- [Session sheet](/ai-ledger/everywhere/sheets/#session-sheet): the whole session, whatever the range filter says.
- [Project sheet](/ai-ledger/everywhere/sheets/#project-sheet): a project over the page's range and source. See also [Project](/ai-ledger/pages/project/).
