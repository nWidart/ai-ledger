Errors answers: which tool calls fail, which error types fail most and fastest, how much time the retry loops cost, and whether a fix worked. It reads the failed tool calls of every coding agent (Claude Code and Codex), sorts each into an error type, groups repeated failures into incidents, and gives each type a ready-made fix to paste into `CLAUDE.md` or `AGENTS.md`. The page is at `/errors`.

Terms such as incident, recovered and error rate are in the [Metric glossary](/ai-ledger/reference/glossary/). A fix is a line to paste into your project's `CLAUDE.md` or `AGENTS.md`, where the agent reads its standing instructions.

## Filters

The [scope bar](/ai-ledger/everywhere/filters/#scope-bar) under the navigation carries the shared filters. Three more controls sit where they act: **Day / Week** in the chart's header, and **Include subagents** and **Hide noise and muted** in the type table's toolbar. The URL keeps all of them, and the page remembers its last view.

| Control | Where | Values |
| --- | --- | --- |
| Project | Scope bar | All projects, or one project. The list shows each project's errors, all time. |
| Time range | Scope bar | 7d, 14d, 30d, 90d, All. The default is 30d. |
| Source | Scope bar | All, Claude Code, Codex. |
| Day / Week | Chart header | The size of a chart bucket. The default is Day. |
| Include subagents | Type table toolbar | On by default. Off leaves out failures of subagents and the calls they made. |
| Hide noise and muted | Type table toolbar | Off by default. On leaves out harness errors, user rejections and the types you muted. |

The two toggles filter the whole page, the summary and the chart included, not only the table. There is no Include automated sessions control on this page. See [Filters](/ai-ledger/everywhere/filters/) for the shared filters.

## Panels

### Summary

<ThemedImage dark={summary} light={summaryLight} alt="Errors' summary figures: the change in the error rate against the previous 30 days, the incidents, the top type and the fixes applied." />

**Shows** the view's answer in the heading, two figures: "N failed tool calls (X%)." X is the error rate. With no failure it reads "No failed tool calls … out of N". With no call it reads "No tool calls in this period". Under it, a line gives the date span. The navigation shows when the store was last ingested.

**Figures**

A line "Uncategorized: N% of errors" gives the share of errors in the catch-all types (Other, Other non-zero exit, MCP tool error): errors that no specific rule matched. Its **How measured** toggletip says so. When the view has errors from both agents and no source filter, it splits the share by agent. A growing catch-all shows at once.

Four vitals follow. None repeats the error rate, which the heading states:

| Vital | Meaning |
| --- | --- |
| Change | The error rate against the comparison period (see below), with both rates in its note. |
| Incidents | Errors grouped into incidents, the share of incidents that did not recover, and the number of error types. |
| Top type | The error type with the most errors, and its share of the errors. "–" with no errors. |
| Fixes applied | Types marked as fixed, and how many open types still have a ready-made fix. |

On a narrow screen the vitals show two to a row. Every line and vital shows at every width.

**How the page compares periods.** The summary, the type table and Rising fastest compare the same way:

- For a range (7d to 90d): the range against the same number of days just before it.
- For All: the calls before and since the day that splits the view's calls in half.
- When either side has fewer than 200 tool calls, Change shows "–" and the page says why ("Fewer than 200 tool calls in the 7 days before").
- A type with fewer than 5 errors on either side shows its counts ("2 → 9": errors in the earlier period, then in the later one) instead of a percent.

### Errors by type

<ThemedImage dark={chart} light={chartLight} alt="Errors by type: the error rate as a line over failed calls per day, on one time axis." />

**Shows** two panels on one time axis. The upper panel is the error rate (errors per 100 tool calls) as a line; the lower panel is the failed calls per day or week as stacked bars. Without calls or without errors the chart is replaced by a message.

**Figures**

- **Legend**: the five types with the most errors, each with its count, then **Other types**. The legend also names the rate line, **Under 50 calls** (a bucket with too few calls for a steady rate: a hollow dot, left out of the rate scale) and **No activity** (a band over buckets with no tool call; a stretch of 8 or more buckets with no call folds into a break marked `//`).
- **Fix markers**: a dashed green line at the day a fix was marked, labelled with the type.
- **Reading**: a failed call counts on the day it started and its error on the day it ended, so a bucket can have errors and no calls; the reading says that no tool call started in it.

**Controls**

- **Day / Week**, in the chart's header, sets the bucket size.
- Select a type in the legend to open it and draw its own rate line.
- **Show data table**, under the chart, lists each bucket: its tool calls, failed calls, the rate the line draws (the open type's, when one is open) and the failed calls of each type in the legend and Other.
- **Reading**: hover, or the left and right arrow keys, Home and End, read a bucket: its rate, errors, calls and errors by type, and "too few calls for a steady rate" for a hollow point. Escape clears the reading.
- **Selecting a bucket**: a click, or Enter or Space on the current point, selects one day or week; the same action clears it. A chip by the Error types heading also clears it. A folded stretch cannot be selected. A selected bucket narrows the type table and the open type's detail to its errors. The summary, the chart, Trend and Change stay range-wide.

### Error types

<ThemedImage dark={types} light={typesLight} alt="The Error types table: one row per type with its count and change." />

**Shows** one row per error type in the view, in four columns. The table fits its panel at every width and never scrolls sideways; on a narrow screen the figures tighten and the sparkline is left out.

**Figures**

| Column | Meaning | Sort |
| --- | --- | --- |
| Type | The type's label, with a swatch matching its chart layer, a **Muted** chip when muted and a **✓ Fix applied** chip with its date when marked. | A to Z first |
| Errors, Rate | Failed calls of the type, then its errors per 100 tool calls in the view, with two decimals. Under them, a bar and a percent give the type's share of the view's errors. | Errors or Rate; the default is Errors, most first. The share orders as Errors does |
| Time lost, Not recovered | Time in retry loops: from each incident's first failure to its last, summed. An incident counts whole when any of its failures is in the view. "–" when no incident of the type has a measurable span. Under it, the share of the type's incidents whose outcome is not recovered, such as "37% not recovered". | Time lost or Not recovered |
| Trend, Change | A sparkline of the type's rate over the whole range, from its first day, with a green tick on the day its fix was applied. Under it, the type's rate against the comparison period, in percent, or counts when either side has fewer than 5 errors. Select the change to see the two rates behind it, or why it shows "–". | Change, by the change in points |

With a bucket selected, the types, Errors, Rate, the share, Time lost and Not recovered follow the bucket; Trend and Change stay range-wide.

**Controls** A click anywhere on a row opens the type; a second click closes it. The toolbar above the table holds a search field, **Filter types…**, which keeps the types whose label or id contains the text and announces "N of M types", and the **Include subagents** and **Hide noise and muted** toggles. Neither the sort nor the filter text is in the URL; they last the page visit.

A column with two figures has a sort button for each, one per line. Press a button, or focus it and press Enter or Space, to sort by its figure; press it again to flip the direction. A row with "–" for the sorted figure comes last in both directions.

### Where to start

<ThemedImage dark={detail} light={detailLight} alt="Errors' Where to start panel: the error types with a ready-made fix, and the fastest rising types." />

**Shows** the panel beside the table while no type is open.

**Figures**

- **Open fixes**: up to four open types (no fix marked, not muted) that have a ready-made fix, with the most time lost in retry loops first, then the most errors. Each shows its errors and time lost and the fix text. Selecting one opens it.
- **Rising fastest**: up to four types whose error rate rose by more than 10% of its earlier value in the comparison, with at least 5 errors now, ordered by the rise in percentage points. A type with few errors shows counts ("0 → 48"). A fixed-noise type carries "noise". The action reads "Check the fix" for a type with a fix marked and "See what changed" otherwise. A muted type is in neither list. Both lists follow the filters, so with **Hide noise and muted** off, an always-noise type that has a ready-made fix (User rejected the action) can be listed.

- **Applied fixes**: every type with a fix marked, newest first, with its fix day, its error rate **Before** the fix and **Since**, and the verdict of the type detail's [before and after](#type-detail) comparison: **Rate lower**, **Rate higher**, **Rate unchanged**, **Not enough calls yet** or **No calls before this date**. Like that comparison, it covers all time under the project, source and subagent filters. The table is absent when no fix is marked.

The panel says "Nothing open with a known fix" and "Nothing is rising in this range" when a list is empty.

**Controls** Selecting an item in either list opens its type. In Applied fixes, a type with errors in the view opens from its name.

### Type detail

**Shows** the open type, in place of Where to start. On a narrow screen (900 px or less) it opens as a sheet. **Back to types** and **✕** close it. The open type is in the URL. A session or tool sheet opened from it stacks over it with **← Back**: Back, Close, Esc or a click beside it returns to the type and to the link.

**Figures** In order:

1. **Why**: one sentence on what the type is.
2. **Incident line**: "N errors in M incidents, X% did not recover", the time lost in retry loops and the largest incident ("Largest: N attempts over 3m"). Its **How measured** toggletip says what an incident is and what recovered means. Durations read in one unit, as on every page: "42s", "7m", "1.5h".
3. **Potential fix**: the fix text, and where one exists a snippet to paste and **Copy instruction line**.
4. **Fix marker**: a date field **Applied on** (today by default, no earlier than the first day of the store) and **Mark fix applied**; once marked, **✓ Fix applied** with the date and **Undo**. A marker applies to all projects. While a write waits the page shows "Saving…"; a failed write shows a message beside the marker.
5. **Mute**: **Mute this type** or **Unmute**. A muted type counts as noise. **Harness / connection failure** and **User rejected the action** are always noise and cannot be muted; the detail says so instead.
6. **Before and after the fix** (after a marker): the error rate before the fix and since it, over all time, for the project, source and subagent filters, with errors and calls on each side. The verdict is **Rate lower**, **Rate higher** or **Rate unchanged** once the calls since the fix are enough for the old rate to have produced 5 errors (and at least 200 calls). Before that it reads **Not enough calls yet**, with how many are needed; with no calls before the marked day it reads **No calls before this date**.
7. **Error rate** sparkline of the type with its fix marker, when the main chart is out of view.
8. **By project**, **By tool**, **By agent**: the top five of each with its count and share, and "N more: M errors" for the rest. A By project row sets the project filter. A By agent row sets the source filter and is hidden under a source filter or when one agent has all the errors. A By tool row narrows this type's detail only (not the page); selecting it again, or its chip by the list heading, clears it. By tool is hidden when the type has one tool.
9. **The list**, in three modes:
   - **Incidents**: 20 at a time, most weight first. A row shows its attempts ("3× attempts"), project, tool, **subagent** when it is one, the outcome, the time span, the successful calls in between, and an attempt strip. Opened, it lists the failures in order and one closing line.

     The **attempt strip** draws each failure as ✕ at its time, then ✓ when the next call succeeded. The strip grows with the time the failures span, so a tight loop is a short strip of crowded marks, and failures minutes apart are a long strip of separate ones. The ✓ always sits a short step after the last failure; the strip does not show how long the recovery took. A screen reader reads the strip as text, such as "3 failed attempts over 4s, 2s apart on average, then the next call succeeded 2s later".
   - **Every error, newest first**: 30 at a time.
   - **By message**: one row per normalized message, with count, message, share of the type's errors, project count, top two tools with "+N", and newest time; opened, its examples newest first, 30 at a time, with **Show more examples**. A **Copy** button copies the normalized message. The page normalizes a message to its first non-empty line, with paths, ids, dates and numbers replaced by `<path>`, `<id>` and `<n>`.

   The mode is remembered. The search box, **Filter by command, error or project…**, narrows the list and the count line ("N of M match"). **Show more** adds the next page.

#### Incidents and outcomes

An incident is a retry loop of one agent: failures of one tool, by one agent (the main thread or one subagent), with one error type, each starting at most 10 minutes after the previous one ended, with at most 2 successful calls of that tool in between. Two subagents make two incidents.

| Outcome | Meaning |
| --- | --- |
| Next call OK (recovered) | The agent's next call of that tool, started after the incident's last failure ended, succeeded. |
| Failed again | That next call failed too, with another error or more than 10 minutes later. |
| Gave up | There was no later call of that tool. |

Recovered means only that the next call succeeded. A call that started before the last failure ended does not count.

#### Examples

An example shows its time, project, tool, **subagent** when it is one, session, the input, the error text and the tool's result. The tool name opens the tool inspector for the page's view. The session link (`#` and 8 characters) opens that session's sheet over the page. **🔗 Link** and **Copy URL** give a permalink to the example; opening it shows its type and example first. The payload cuts long inputs; **Show full** loads the rest, and **Show less** folds it back. A permalink whose example the store no longer holds shows a notice ("The linked error is no longer in the store…") and the view without it. A linked example that the filters hide shows under **Outside current filters**, with **Clear filters**.

## Sheets

- The **tool inspector** opens from a tool name on an example, for the page's view.
- The **session sheet** opens from a session link on an example, over the page: the open type and the examples stay as they are, and Close or Back returns to them. The URL names the session, so `/errors?range=7&session=abc&cat=x` opens type `x` with that session's sheet. Middle-click opens it in a new tab. ## Error type rules

The app sorts each failed call into the first rule that matches. The page shows the label; the id appears in URLs and matches the type filter.

| Label | Id | Ready-made fix |
| --- | --- | --- |
| Path outside isolated worktree | `worktree` | Yes |
| Command too complex for worktree check | `worktree_verify` | Yes |
| Sleep-then-poll blocked | `sleep_poll` | Yes |
| ls aliased to eza | `ls_alias` | Yes |
| Wrong CLI flags (BSD vs GNU, gh) | `cli_flags` | Yes |
| zsh glob had no matches | `zsh_glob` | Yes |
| Command not found | `cmd_not_found` | Yes |
| File or directory not found | `no_file` | Yes |
| Edit/Write before Read | `edit_unread` | Yes |
| File changed since read | `edit_stale` | No |
| Edit old_string mismatch | `edit_nomatch` | Yes |
| User rejected the action | `user_denied` | Yes; always noise |
| Permission / safety check denied | `perm_denied` | No |
| Blocked by hook or harness rule | `hook_block` | No |
| Wrong tool name or parameters | `bad_call` | No |
| Harness / connection failure | `infra` | No; always noise |
| Network / DNS unreachable | `network` | Yes |
| Browser automation failed | `browser` | Yes |
| Command timed out | `timeout` | Yes |
| grep/rg found nothing (exit 1) | `search_empty` | Yes |
| Chained command: one step failed | `chained` | Yes |
| Tests / build / lint failed | `tests` | Yes |
| git / gh error | `git` | Yes |
| Script error (Python/Node) | `python` | No |
| OS permission / sandbox | `os_perm` | No |
| Other non-zero exit | `exit_other` | No; catch-all |
| MCP tool error | `mcp` | No; catch-all |
| Other | `other` | No; catch-all |

## Muting and noise

A type you expect, such as `grep/rg found nothing (exit 1)`, can be muted from its detail. A muted type counts as noise: with **Hide noise and muted** on, it is out of the error rate, the chart, the type table, the comparison with the period before and the Uncategorized share. It never appears in Where to start, whatever the toggle says, and the Fixes applied vital leaves it out of the open count.

The fix markers and the muted types live in the store, so they follow you to another port, browser or profile. A change made in another tab shows on the next load.
