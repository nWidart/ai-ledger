Live answers one question: which of my sessions are running, and which wait for me? It follows each active Claude Code, Codex and Grok session within seconds of its transcript lines being written, from the agent's side: prompts, tool calls, subagents, context and cost.

:::caution[Full text shows transcript content, secrets included]
Live shows word counts, shortened tool inputs and subagent descriptions by default. The **Full text** toggle puts transcript content on screen, secrets included. It is off on every page load. Turn it off before you share your screen. See [Privacy and security](/ai-ledger/concepts/privacy-security/).
:::

Terms such as compaction, subagent and automated session are in the [Metric glossary](/ai-ledger/reference/glossary/).

A session is **active** when its newest stored line is less than 10 minutes old. Live lists active sessions only. With none, the page says "No session is active in this view." and, when a session exists, links to the newest one with the time it last wrote. The link opens that session's sheet over the page.

## Filters

The [scope bar](/ai-ledger/everywhere/filters/#scope-bar) under the navigation holds the shared project picker, **Source** and **Include automated sessions**. Live has no range filter. The project picker lists the projects of the active sessions. Changing the project or source closes an open session sheet, as on the other pages.

The bar beside the heading holds, in this order:

| Control | What it does |
| --- | --- |
| **Stream** / **Wall** | Switches between one session in detail and every session as a tile. |
| **Follow** | Stream view only. Keeps the newest event in view. On at load. Opening a session turns it on again. |
| **Full text** | Shows transcript text as written. Off on every load. When you turn it on, a warning opens under the bar, over the page: "Full text on. Prompts, replies and tool output show as written, secrets included. The app only listens on 127.0.0.1; turn this off before sharing your screen." **Dismiss** closes it. The warning takes no room, so the stream does not move when it opens or closes. While Full text is on, the toggle keeps a warning tint, also after you dismiss the warning. |
| **Pause** / **Resume** | Holds new events and states until you resume. |

In the bar, before **Follow**, a status says one of: "Connecting…", "Updating live", "Paused" (with the number of updates held), or "Connection lost · reconnecting…". A paused page shows no live dot, and its state dots do not pulse. After a lost connection the page retries on its own, waiting longer after each failure up to 30 seconds, and fetches what it missed when it is back.

The URL keeps the selected session, the view, the Wall's pins (`pin=`, oldest first), and the project, source and automated filters. Pinning and unpinning replace the current history entry, so Back does not step through pins. Full text, Pause and the stream filters are off on every load. Follow is on on every load.

Live keeps one update connection while the tab shows. Pinning, unpinning, switching between Stream and Wall, and opening or closing a sheet do not open another.

In a background tab, Live stops its requests and timers. When you return, it fetches what it missed and resumes. A page you paused stays paused.

The tab title carries the number of sessions that need you, as in `(2) Live · AI Ledger`. Sessions that need you are those in **approval?** and **your turn**. With none, the title has no count.

On every page, the **Live** tab in the navigation carries the same kind of count as a badge: the sessions in **approval?** and **your turn**, over every project and every agent, with automated sessions left out. It shows nothing at 0 and "9+" above nine, and it follows the navigation's status check, about once a minute and when you return to the tab. Live's own list is filtered and updates every second, so the two can differ for a moment.

## Panels

The Stream view has two panels from left to right: the rail and the session's stream, with the status strip at the top of the stream. At 721 pixels wide and up the page fits the window's height and each panel scrolls inside itself. Below that width the page scrolls as any other, and the rail is one row of entries that scrolls sideways inside itself, so the stream starts on the first screen of a phone. The Wall view replaces the two panels with one tile per session, and up to two pinned streams beside the tiles.

### Active sessions rail

<ThemedImage dark={rail} light={railLight} alt="Live's Active · last 10 min rail: the active sessions, grouped by state." />

**Shows** the active sessions. The panel heading reads "Active · last 10 min". Sessions sit under a heading per state group, `label · count`, in this order: **approval?**, **your turn**, **working**, **idle**, **ended**. A group with no session is not drawn. Inside a group, sessions are ordered by session start, oldest first, so an entry moves only when its state changes group. Keyboard focus follows a session that changes group.

**Figures**

Each entry shows:

- the session's title as its main line, or the project when the session has no title;
- its cost so far;
- on the second line, the project (with its color), the state with its time, and the source (Claude Code, Codex or Grok). An entry with no title shows the state, the source and the git branch instead;
- on the third line, a small context meter with the percent of the window used (left out when the window is not known), the latest action as the wall tile shows it, and `✕ N` when calls failed. A screen reader reads `✕ N` as "N errors".

The footer reads `N sessions working · N waiting for you · $ so far`; the "waiting for you" part shows only when at least one session waits. Working counts the working group. Waiting counts approval? and your turn. Idle and ended count as neither.

A session's title comes from the newest custom title (Claude Code `/rename`), else the agent's own title (a Claude Code AI title or a Codex thread name; Grok's title is not recorded), else, only with Full text on, a title made from the first prompt. A title has at most 80 characters.

**Controls** Selecting an entry opens that session in the stream. With no session selected, the page opens the newest active session.

### Session stream

<ThemedImage dark={stream} light={streamLight} alt="Live's session stream: a prompt, the reply, tool calls, a subagent lane and a failed npm test." />

**Shows** the selected session as a log of its events in order, newest at the bottom. The head shows the session's title as a heading (the project when there is no title), then the project, git branch, source and model, and a **Session sheet** link. The status strip under it shows the state. The link opens the session's sheet over Live: the stream keeps updating under it, and Close or Back returns to it. On Live the URL names the sheet as `sheet`, because `session` names the session the stream follows: `/live?session=abc&sheet=abc`. The time column shows the clock time, with the date for an event not from today.

When older events are not shown, the stream says so and links to the session sheet, which holds the whole session. A session with state your turn ends the stream with "waiting for your next prompt".

**Figures**

| Event | What the row shows |
| --- | --- |
| Prompt, Reply | With Full text off, a word count. With it on, the text as written. |
| Tool call | The tool, its row text, its duration and its result: a timer while running, then ✓ passed or ✕ failed. A shell call with a description shows the description as its row text, otherwise the input summary. An MCP tool shows by its tool part, with the full name on hover. |
| Compaction | A mark between events: "context compacted at N tokens". |
| Interruption | "interrupted by you". |

A tool row opens its detail in place: the description (shell calls), the input, the start time, the error when it failed, and the result. With Full text off, the result shows only its size in characters. A tool input is cut to 300 characters with Full text off. The error text of a failed call shows with Full text off too, up to 700 characters. A failed command inside a Codex `exec` script gets its own failed row.

**Subagent lanes.** Subagent work shows as a lane inside the stream. The header shows the subagent's name, its description, its tool count, its error count when above zero, its duration, its model and cost when known, and whether it is running (spinner) or done (✓). A finished lane is folded. A running lane with more than 5 rows shows its last 5, with a control under its header ("Show all N rows", then "Show last 5"). The Errors filter opens a finished lane that holds a failed row, unless you folded it. A fold or expansion you chose is kept while the page is open. A Grok subagent runs as a session of its own in Grok's files; Live shows it as a lane of its parent session, never as an entry of its own.

**Controls**

Under the status strip, a **Stream filters** bar holds:

| Filter | Effect |
| --- | --- |
| Errors count (`N errors`, "show failed calls only") | Shows failed tool calls only. Select it again to clear it. The status strip's Errors figure is the same control. |
| **Main thread only** | Hides every subagent lane. |
| **Hide read-only** | Hides calls that only read: `Read`, `Grep`, `Glob`, and shell calls whose every command only reads or searches. A failed call is never hidden. |

The filters combine, stay on when you open another session, and change only what the stream draws, not the status strip's figures or a lane header's counts. The stream says how many rows the filters hide.

- Select a tool row to open its detail.
- Select a lane header to fold or unfold the lane.
- **Follow.** With Follow on, the stream keeps the newest event in view. Scrolling up or opening a tool row turns Follow off. While Follow is off and new events arrive, **Jump to latest ↓** appears with "N new events" beside it, in a polite status. It counts the events since Follow turned off, however you turned it off. The count shows at once, then changes at most once every 5 seconds. Jump to latest turns Follow on again. With Follow on, the page announces nothing for new events.

### Status strip

<ThemedImage dark={strip} light={stripLight} alt="Live's status strip above the stream: the state, the context meter, cost, tools, errors, cache read, plan limits, the pulse, the directory and Copy resume." />

**Shows** the selected session's figures, in a strip at the top of the stream, under its head. Grok reports its usage once per turn, so a Grok session's tokens, cost and context change when a turn ends, not while it runs. It belongs to the stream's panel: it is not a bar across the page. It wraps onto a second line when the stream is narrow.

**Figures** In order:

| Item | Figures |
| --- | --- |
| State | The state and its detail, such as "Bash pending 45s: likely waiting for your approval". An inferred state shows **(inferred)**, a toggletip that gives the reason. |
| Context | The context of the newest main-thread request out of the model's window, such as `55k / 1M · 6%`, with a meter and a mark at each compaction, then the compaction count. The meter turns to the warning color above 80%. With no known window, it shows tokens only and says the window is not known. |
| **Cost**, **Tools**, **Errors** | The session's cost, tool calls and failed tool calls so far. |
| **Cache read** | The share of the session's prompt tokens read from the cache, with a toggletip that says so. |
| Plan limits | One item per open plan limit of the session's source, such as `5h 42%`. Above 80% it takes the warning color and adds "near". A toggletip beside it gives the reset time, by pointer, tap or keyboard; the [Limits](/ai-ledger/pages/limits/) page shows every window in full. |
| Pulse | The last 10 minutes (see below). |
| Directory | The session's working directory, cut from its start so the end of the path shows. A screen reader reads the whole path. Below 721 pixels wide it takes its own line beside Copy resume. |

The strip shows no request count or model: the model is in the stream's head, and the session sheet's Models table counts the requests of each model.

**The pulse** draws the last 10 minutes of the session. A line follows the context of each main-thread request, so it rises as the context grows and stays flat when requests only reread the cache. It is scaled from its lowest to its highest value, so small growth shows; the readout gives the numbers. Along the foot, each tool call that ended has a tick: an upright line for a success, a ✕ for a failure. Subagent calls count too. The pulse's name gives its summary to a screen reader, such as "Last 10 minutes: context 40k to 62k tokens, 18 tool calls, 2 failed." The range is the lowest and highest context the line plots, so a peak shows even when the context fell back; a flat line names one level. Tab to it and use Left and Right to read one minute at a time, Home and End for the first and the last, and Escape to dismiss the readout. The readout, such as "10:04 to 10:05: context 52k, 3 calls, 1 failed", shows under the pulse and is read politely. Below 721 pixels wide it shows under the strip and wraps, so it stays on the screen. Hovering it reads the minute under the pointer.

**Controls**

- The Errors figure toggles the Errors stream filter.
- **Copy resume** copies the command that resumes the session in its agent, `claude --resume <id>`, `codex resume <id>` or `grok --resume <id>`, after `cd '<directory>' && ` when the directory is known. It says "Copied" or "Copy failed", politely to a screen reader too.

### Wall

<ThemedImage dark={wall} light={wallLight} alt="Live's Wall view: one tile per active session." />

**Shows** one tile per active session, grouped by state under the rail's headings (`label · count`), in the same order. Each group is a list under an `h2` heading. Inside a group, tiles are ordered by session start, oldest first.

**Figures** A tile shows, top to bottom:

- the project and the state;
- the title on one line, cut with an ellipsis, with the full title on hover (left out when the session has no title);
- the latest action: `▸ prompt`, or `Tool · summary`, with `⤷` before a subagent's call. A shell call with a description shows the description;
- a context meter, and `context N%`;
- the tool count, the error count when above zero, and the cost;
- the git branch, the source and the model.

A tile's border follows its state: your turn, approval? and running a tool each have a colored border, and ended has a dashed one. Thinking and idle tiles have the panel's usual border.

**Controls** Selecting a tile pins its stream beside the tiles, and selecting it again unpins it. A pinned tile says **Pinned**, and a screen reader reads it as a pressed button. Its name is "Pin" and the session, then all the tile shows, in words: the project (when a title names the tile), the state and its detail, the latest action, the context, tools, errors and cost, then the branch, source and model. The name follows each update. The Wall holds two pinned streams at most: pinning a third unpins the oldest, and a status says so, such as "Pinned graft. Unpinned notes: 2 pins at most."

A pinned stream shows its head, a status strip without the directory and Copy resume, and its stream, with its own stream filters and its own Follow, on when pinned. Its head has:

- **Session sheet**, which opens the session's sheet over the Wall. The pinned streams keep updating under it.
- **Open in Stream**, which opens the session in the Stream view and puts the keyboard focus on the stream's heading. The pins stay in the URL for when you come back to the Wall.
- **Unpin**, which removes the stream and puts the keyboard focus on the session's tile. When the session has no tile, because it left the active list or the store does not hold it, the focus goes to the other pin's first button, else the first tile, else the page's heading.

A pinned session stays pinned when it ends or leaves the active list. While a pin first loads, it says "Loading…" and a screen reader reads it as busy. When an update fails, the pin keeps its stream and says "Could not update this session." A pin the store does not hold says "Session not found", and Unpin still removes it.

The URL's `pin=` keeps each well-formed id once, at its first place; of more than two, the last two stay. `pin=a,b,a,c` pins b and c.

From 1100 pixels wide, the tiles stand in one column with the pinned streams beside them, and the page fits the window's height. Below that, the pinned streams go under the tiles.

## Session states

Each active session has one state. The rail, the wall and the status strip use these words.

| State | Group | Meaning |
| --- | --- | --- |
| **approval?** | approval? | A shell call (`Bash`, Codex `exec` or `exec_command`, Grok `run_terminal_command`) with no result for more than 30 seconds. Inferred: transcripts record no permission prompt. A shell call with a timeout above 120 seconds does not count. |
| **your turn** | your turn | The agent finished its turn and waits for your prompt. The label counts up how long. A cancelled Grok turn counts as an interrupt and ends the turn too. |
| running a tool | working | A tool call has no result. The label names the tool and how long it has run, such as `Read 4.2s`. |
| **thinking** | working | The newest main-thread line is your prompt or a tool result. Inferred for Claude Code. Not inferred for a Codex or Grok turn, which the agent records: a Grok session reads thinking from its prompt to the end of its turn. A session whose subagent is at work reads thinking, inferred, even when the main thread finished its turn. |
| **idle** | idle | No line for 5 minutes. |
| **ended** | ended | A Claude Code session you closed, or a Grok session after Grok exits. Codex writes no close, so a Codex session goes from your turn to idle and never reads ended. |

An inferred state shows "(inferred)" beside it, with the reason as hover text, and in the status strip behind its **(inferred)** toggletip.
