# Tasks

How to read a step:

- **Order.** "After X" means the step needs X merged first. "Parallel with X" means the two touch different files and can be built at the same time.
- **Risky.** A mistake in the step can pass its checks and still be wrong. The step says what the checks cannot see, and which step catches it.
- **Model.** The smallest model that can do the step reliably: Sonnet for a well-defined or mechanical step and for docs, Opus for standard building. No step needs a larger model.
- **Check.** Web steps run, from `web/`: `npm run typecheck`, `npm run lint`, `npx vitest run --maxWorkers=4`, `npm run build`, `node scripts/check-bundle.mjs` (or `npm run check`, which runs the first four). The step names the tests that must exist and pass.
- **Browser.** Only steps 4.1 and 4.2 start a browser. Run them one after the other, in one slot. No other step starts a browser, Playwright or the demo server.
- **Checkboxes.** A builder does not tick a box: steps run in parallel, and the boxes would conflict. Step 4.3 ticks them all.
- All design references are to `design.md` in this change. Change files with the Edit and Write tools only.
- **Never edit** `web/src/components/echart/EChart.tsx`, `option.ts`, `stack.ts`, `testing.ts`, `zoomReset.tsx`, `realTesting.ts` or `echarts.ts`, nor `web/src/pages/context/SessionMap.tsx`. If a step seems to need it, stop and report.
- Tests follow the "Tests" section of `AGENTS.md`: add an assertion to the test that already builds the fixture or the render; test a rule once, at the layer that owns it; export nothing only for a test.
- The new files live in `web/src/pages/project/quadrant/`. Fresh worktree: `cd web && npm ci && npm run build` before the Python tests.
