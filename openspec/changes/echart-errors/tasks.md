# Tasks

How to read a step:

- **Files.** What the step may change. A step changes no other file; if it must, it stops and says so.
- **Order.** "After X" means the step needs X merged first. "Parallel with X" means the two touch different files and can be built at the same time.
- **Browser.** The step runs a real browser. Only one such step runs at a time, with no other step running a build or a server: 3.3, then 3.4, then 3.5, then 3.6.
- **Risky.** A mistake in the step can pass its checks and still be wrong. The step says what the checks cannot see, and which step catches it.
- **Model.** The smallest model that can do the step reliably: Sonnet for a well-defined or mechanical step, docs and images; Opus for standard building; Fable 5.2 only where the wrapper's contract changes.
- **Check.** Every step that touches `web/src` ends with `cd web && npm run check`. The step names the tests that must exist and pass. A fresh worktree needs `cd web && npm ci` first.
- **Checkboxes.** A builder does not tick a box: steps run in parallel, and the boxes would conflict. Step 3.6 ticks them all.
- All design references are to `design.md` in this change. "The foundation" and "the Activity design" are the two archived designs it names. Read `AGENTS.md`, its "Tests" section included, before writing a test. Change files with the Edit and Write tools only.
